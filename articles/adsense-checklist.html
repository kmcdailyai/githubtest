애드센스 신청 전 점검표: 사이트 추가부터 ads.txt까지

새벽뉴스 편집부 · 2026년 10월 15일 · 수익화

애드센스 신청은 코드 몇 줄 붙이는 것으로 끝나지 않았습니다. 사이트 추가 단계에서 막혔고, 코드를 넣은 뒤에는 사이트 자체를 다시 돌아봐야 했습니다. 직접 겪은 순서대로 정리합니다.

1. 사이트 추가가 안 될 때

Cloudflare Pages가 보여 준 71f5173e.githubtest2.pages.dev 같은 주소를 넣었더니 추가되지 않았습니다. 이 주소는 배포할 때마다 바뀌는 회차 전용 주소이고, 검색 로봇을 막는 noindex 표시가 붙어 있었습니다. 앞부분을 뗀 githubtest2.pages.dev를 넣자 바로 추가되었습니다. 자세한 차이는 무료 배포하기 글에 있습니다.

2. 애드센스가 준 세 가지를 넣는 곳

받은 것넣는 곳하는 일
<meta name="google-adsense-account" …>모든 페이지의 <head>이 사이트가 내 계정 것임을 확인
<script … adsbygoogle.js …>광고를 보여 줄 페이지의 <head>광고 표시 (승인 전에는 아무것도 보이지 않음)
google.com, pub-…, DIRECT, …사이트 맨 위 폴더의 ads.txt 파일내 광고 계정만 광고를 팔 수 있다고 공개 선언

ads.txt는 사이트주소/ads.txt로 열었을 때 그 한 줄이 그대로 보이면 제대로 올라간 것입니다. 애드센스 화면에서 바로 인식하지 못해도, 다시 읽어 갈 때까지 시간이 걸릴 수 있습니다.

3. 코드보다 중요한 것: 콘텐츠

애드센스 한국 공식 블로그의 고품질 사이트를 만들기 위한 도움말과 2부를 읽고, 이 사이트에 맞춰 점검할 항목으로 바꿔 보았습니다.

도움말의 요지이 사이트에서 한 일
잘 알고 열중할 수 있는 주제에 집중지어낸 예시 기사를 모두 지우고, 사이트를 직접 만들며 겪은 일만 쓰기로 함
다른 곳과 차별화된 독창적 콘텐츠실제로 막혔던 지점(미리보기 주소, 댓글 색 문제 등)과 해결 과정을 기록
중복되거나 내용이 거의 없는 페이지 금지한 사이트에 모으고, 글마다 다른 주제를 다룸
약속한 정보를 그대로 제공글 제목과 요약이 본문 내용과 일치하게 씀
쉬운 탐색 구조모든 페이지에 같은 메뉴, 홈에서 분류별로 글 찾기
광고보다 콘텐츠가 먼저광고는 자동 광고 한 가지만 사용
콘텐츠가 아닌 페이지에는 광고 금지문의 페이지와 404 페이지에는 광고 코드를 넣지 않음

4. 신청 전 마지막 점검표

  • 사이트 소개 페이지가 있는가: 소개
  • 개인정보처리방침에 광고 쿠키, 문의 폼, 댓글 정보를 적었는가: 개인정보처리방침
  • 방문자가 연락할 방법이 있는가: 문의
  • "테스트", "예시", "준비 중" 같은 문구가 남아 있지 않은가
  • 모든 메뉴와 링크가 실제 페이지로 이어지는가
  • 휴대폰에서도 읽기 편한가
  • 글이 꾸준히 늘고 있는가

승인 여부는 구글이 정합니다. 이 점검표는 승인을 보장하지 않고, 도움말이 말하는 기본기를 갖추었는지 스스로 확인하는 용도입니다. 도움말의 결론처럼 지름길은 없고, 방문자에게 쓸모 있는 글을 꾸준히 쌓는 것이 가장 확실한 길입니다.

함께 읽으면 좋은 글

  • 코딩을 몰라도 홈페이지를 만들 수 있을까: HTML, CSS, 자바스크립트의 역할
  • GitHub와 Cloudflare Pages로 무료 배포하기: git push 한 번이면 끝
  • 다크모드 제대로 만들기: 선택 기억, 기기 설정 따르기, 깜빡임 막기
